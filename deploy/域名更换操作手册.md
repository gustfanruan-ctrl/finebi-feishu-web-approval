# 域名更换操作手册（FineBI × 飞书权限申请系统）

> 适用场景：客户更换了对外域名，旧子域名解析/证书失效，系统需要通过新域名继续访问。
> 本文中 `NEW_DOMAIN` 代表客户提供的新域名，`APP_HOST` 代表应用服务器，`ENTRY_NGINX` 代表客户入口 NGINX。
> 操作前先确认：**应用服务器和客户入口 NGINX 可能不是同一台机器；证书和域名解析通常由客户运维负责。**

---

## 0. 先确认影响范围

域名只影响“浏览器/飞书访问入口”，不影响 FineBI 开放平台调用。需要同步修改 4 处：

| 位置 | 需要改什么 | 谁负责 |
| --- | --- | --- |
| DNS | 新域名 A 记录指向**入口 NGINX** 公网 IP | 客户网络/域名管理员 |
| 入口 NGINX | 新域名 `server_name`、443 证书、反代到应用 18080 | 客户运维 |
| 应用 `.env` | `PUBLIC_BASE_URL`、`FEISHU_OAUTH_REDIRECT_URI` | 我方/应用运维 |
| 飞书开放平台 | 重定向 URL 白名单加入新回调地址 | 飞书应用管理员 |

只改其中一处，会出现：
- 能打开页面但飞书登录 `redirect_uri` 不匹配；
- 登录后跳回旧域名/登录页；
- 飞书卡片、审批链接仍指向旧域名；
- HTTPS 证书不受信或 502。

---

## 1. 变更前准备（必须）

### 1.1 收集信息

- 新域名：`NEW_DOMAIN`
- 新域名由谁解析、TTL 多少
- 入口 NGINX 的登录方式/负责人
- 新证书：客户已有证书，还是用 certbot 申请；是否为内部 CA
- 飞书应用管理员：能把新回调地址加入白名单
- 应用服务器：`APP_HOST`、应用目录 `/data/finebi-feishu`、服务名 `finebi-web`

### 1.2 备份

在应用服务器：

```bash
cd /data/finebi-feishu
sudo cp .env ".env.bak.$(date +%F-%H%M)"
sudo systemctl status finebi-web --no-pager | head -10
curl -fsS http://127.0.0.1:18080/health
```

在入口 NGINX：

```bash
# 找到当前 server 配置文件
sudo nginx -T | grep -nE 'server_name|ssl_certificate'
# 备份实际配置目录（按客户路径替换）
sudo cp -a /etc/nginx /etc/nginx.bak.$(date +%F-%H%M)
```

### 1.3 确认切换策略

优先选：

1. **新子域名**：新增一个 `server` 块，旧配置先保留，最安全；
2. 旧域名仍可用时：旧域名 301 到新域名，给用户过渡；
3. 旧域名已失效：直接启用新域名，不需要保留旧入口。

> 不要在新域名下挂子路径（如 `https://NEW_DOMAIN/finebi/`），系统必须挂在根路径 `/`。

---

## 2. 配置 DNS

在客户 DNS 控制台新增/修改：

```text
类型: A
主机记录: 新域名前缀（例如 finebi-app）
记录值: 入口 NGINX 的公网 IP
TTL: 300（切换期短 TTL）
```

验证：

```bash
dig +short NEW_DOMAIN
# 应返回入口 NGINX 公网 IP，不能是应用服务器内网 IP
```

如果客户用 CNAME/SLB/WAF，确保最终转发到入口 NGINX，并保留 `Host`。

---

## 3. 配置入口 NGINX

在**入口 NGINX**增加新域名 server 块（示例，按客户实际证书路径改）：

```nginx
upstream finebi_feishu_app {
    server APP_HOST:18080;   # 应用服务器内网 IP 或可达地址
}

server {
    listen 80;
    server_name NEW_DOMAIN;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name NEW_DOMAIN;

    ssl_certificate     /etc/nginx/ssl/NEW_DOMAIN/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/NEW_DOMAIN/privkey.pem;

    client_max_body_size 20m;

    location / {
        proxy_pass http://finebi_feishu_app;
        proxy_http_version 1.1;

        # 必须透传，否则飞书登录/跳转/来源校验会错
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_connect_timeout 10s;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

执行：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

> 如果入口 NGINX 是客户 Docker 容器：把新 `server` 文件放到容器挂载的 `conf.d/`，然后执行
> `docker exec <nginx容器名> nginx -t && docker exec <nginx容器名> nginx -s reload`；
> 不要重建容器，避免把其它业务站点配置一起重置。

验证：

```bash
# 在入口 NGINX 上验证 Host 路由
curl -fsS -H "Host: NEW_DOMAIN" http://127.0.0.1/health

# 从外部验证
curl -I https://NEW_DOMAIN/
curl -fsS https://NEW_DOMAIN/health
```

预期：`/health` 返回 `{"status":"ok",...}`，不是 502/默认页。

> 客户如果用内部 CA，访问该域名的浏览器/飞书客户端需信任对应根证书，否则飞书内置浏览器可能打不开。

## 4. 修改应用 `.env`

在应用服务器 `/data/finebi-feishu`：

```bash
cd /data/finebi-feishu

sudo sed -i 's#^PUBLIC_BASE_URL=.*#PUBLIC_BASE_URL=https://NEW_DOMAIN#' .env
sudo sed -i 's#^FEISHU_OAUTH_REDIRECT_URI=.*#FEISHU_OAUTH_REDIRECT_URI=https://NEW_DOMAIN/auth/feishu/callback#' .env

grep -E '^(PUBLIC_BASE_URL|FEISHU_OAUTH_REDIRECT_URI)=' .env
sudo systemctl restart finebi-web
sudo systemctl status finebi-web --no-pager | head -10
```

要求：

- 必须是 `https://`；
- 域名必须与实际访问地址**逐字一致**；
- 回调地址必须是 `https://NEW_DOMAIN/auth/feishu/callback`；
- **不要**在末尾加 `/`；
- `PUBLIC_BASE_URL` 决定飞书卡片、审批链接、OAuth 跳转和 Cookie Secure，不要漏改。

> 如果入口 NGINX 上还有旧的 `server` 块，切换期可以保留；但应用 `.env` 只能有一个当前对外地址。

---

## 5. 修改飞书开放平台

由飞书应用管理员操作：

1. 打开飞书开放平台 → 企业自建应用（本系统应用）；
2. 进入「安全设置」/「重定向 URL」；
3. 新增：

```text
https://NEW_DOMAIN/auth/feishu/callback
```

4. 保存；
5. 如果应用有网页应用首页/工作台地址，也改成 `https://NEW_DOMAIN/`；
6. 切换验证期间建议**保留旧回调地址**，验证通过并观察 24–48 小时后再删除旧地址。

注意：

- 飞书要求精确匹配，`http`/`https`、域名、路径、末尾 `/` 任一不同都会报 `redirect_uri` 不匹配；
- 飞书后台改完可能需要重新打开应用/重新登录；
- 如果旧卡片已经发出，卡片里的旧链接不会自动改；新申请/新卡片才会使用新域名。

## 6. 验证清单

### 6.1 服务器侧

```bash
# 应用本机
curl -fsS http://127.0.0.1:18080/health

# 经入口 NGINX
curl -fsS -H "Host: NEW_DOMAIN" http://127.0.0.1/health

# 对外域名
curl -I https://NEW_DOMAIN/
curl -fsS https://NEW_DOMAIN/health

# 查看最近日志
journalctl -u finebi-web -n 100 --no-pager
```

### 6.2 浏览器/飞书侧

- [ ] 打开 `https://NEW_DOMAIN/`，能跳转飞书登录；
- [ ] 飞书登录回调成功，不出现 `redirect_uri` 错误；
- [ ] 登录后进入工作台，不再跳回登录页；
- [ ] 管理员打开 `https://NEW_DOMAIN/admin/login` 能登录；
- [ ] 新建一张申请单，详情链接域名为新域名；
- [ ] 审批人收到的飞书卡片链接为新域名；
- [ ] 手机飞书内置浏览器能打开；
- [ ] HTTPS 证书受信任，无混合内容告警。

### 6.3 边界检查

- [ ] 外网只开放入口 NGINX 的 80/443；应用 18080 不对公网开放；
- [ ] `PUBLIC_BASE_URL` 与 `FEISHU_OAUTH_REDIRECT_URI` 无旧域名残留；
- [ ] 飞书白名单同时有新旧回调（过渡期）；
- [ ] 旧域名如仍可解析，301 到新域名，确认 OAuth 不形成循环。

---

## 7. 切换与回滚

### 7.1 切换顺序（推荐）

1. 先配 DNS/证书/NGINX，新域名能访问 `/health`；
2. 再改飞书重定向 URL（新旧都保留）；
3. 再改应用 `.env` 并重启；
4. 最后对外通知用户新地址；
5. 观察 24–48 小时后再删除旧域名/旧回调。

### 7.2 回滚

如果新域名验证失败：

```bash
# 应用回滚
cd /data/finebi-feishu
sudo cp .env.bak.YYYY-MM-DD-HHMM .env
sudo systemctl restart finebi-web

# 入口 NGINX 回滚
sudo cp -a /etc/nginx.bak.YYYY-MM-DD-HHMM/. /etc/nginx/
sudo nginx -t && sudo systemctl reload nginx
```

飞书后台保留旧回调地址，回滚后旧域名可继续登录；DNS 回滚按客户 TTL 等待生效。

## 8. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 打开域名是默认 NGINX 页 | 新域名 `server_name` 是否写对；是否有默认 server 抢占 |
| 502 Bad Gateway | `APP_HOST:18080` 是否可达；`systemctl status finebi-web`；安全组 |
| `redirect_uri` 不匹配 | 飞书白名单、`.env`、浏览器实际地址三者逐字一致 |
| 登录后跳回登录页/旧域名 | `PUBLIC_BASE_URL` 是否还是旧值；重启 `finebi-web`；Cookie 是否 Secure |
| HTTPS 证书不受信 | 证书是否覆盖新域名；证书链是否完整；内部 CA 是否被客户端信任 |
| 页面样式/跳转异常 | 是否挂在子路径；必须根路径 `/` |
| 飞书卡片还是旧链接 | 旧卡片不会自动更新；新申请/新审批才会用新域名 |
| 换域名后所有人要重新登录 | 正常现象，域名变了旧 Cookie 不再使用 |
